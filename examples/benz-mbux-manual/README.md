# Benz-style IVI manual scaffold

A starter knowledge profile for a **custom OEM IVI** (MBUX-style): custom home
screen, vehicle settings, climate, and seat-massage screens. It exists so you can
drop in **real crops** and be productive immediately.

> ⚠️ Everything in `images/` is a **placeholder** generated by
> `scripts/generate_benz_manual_images.py`. Replace each file with a real
> screenshot / icon crop from the target unit before using this profile against a
> device. Recognition quality depends on real icons + good `meaning`/`synonyms`.

## Structure (`manual.json`)

- **icons** — `climate`, `seat_massage`, `vehicle_settings`. Each has a `meaning`
  and rich `synonyms`; these drive retrieval of proprietary controls.
- **screens** — `home`, `vehicle_settings`, `climate`, `seat_massage`, each with
  `landmarks` and `controls` (id, name, `icon_id`, action, result).
- **tasks** — `open_climate`, `start_seat_massage`, as ordered steps with
  `milestone`/`expected`, plus `success` and `forbidden` guards.

## Use it

```bash
pip install -e '.[docs]'          # reportlab + pypdf
brew install poppler              # pdftoppm, needed to index

# (optional) regenerate the placeholder images
python scripts/generate_benz_manual_images.py --output examples/benz-mbux-manual/images

# build -> index -> sanity check
ivi-agent manual build --source examples/benz-mbux-manual --output output/pdf/benz.pdf
ivi-agent knowledge index output/pdf/benz.pdf --profile benz
ivi-agent knowledge query --profile benz --goal "Start the seat massage"

# run the agent with the profile (bench, stationary unit only)
ivi-agent --config config.json run --serial IVI_SERIAL --display-id DISPLAY_ID \
    --knowledge-profile benz --goal "Open the climate screen"
```

## Customizing for your unit

1. Capture real screenshots (`adb exec-out screencap -p`) and crop each icon.
2. Replace the files in `images/` (keep the same names, or update `manual.json`).
3. For every icon, write a precise `meaning` and generous `synonyms` (how a user
   would name it). This is the single biggest lever on recognition.
4. Add screens/tasks for the flows you want to test; keep `forbidden` lists strict
   for anything safety-relevant.

## Semantic retrieval (optional, recommended for proprietary icons)

Turn on embeddings in `config.json` for better paraphrase/icon recall:

```json
{
  "use_embeddings": true,
  "embedding_model": "nomic-embed-text",
  "icon_matching": true,
  "clip_model": "ViT-B-32"
}
```

- Text embeddings use a local Ollama model (`ollama pull nomic-embed-text`) — no
  extra Python dependency.
- `icon_matching` (CLIP image matching of a live crop against the manual icons)
  needs the optional extra: `pip install -e '.[clip]'`.
- Both degrade gracefully to keyword retrieval when unavailable.
